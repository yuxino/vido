# Vido 2 implementation scope

User direction: rebuild the old Vue 1 player as a modern, lightweight project component, with a cute personal-avatar progress marker and optional DIY appearance. Explicitly approved a new 2.0 architecture.

Decisions: framework-free TypeScript, native video as source of truth, progressive enhancement of existing markup, framework-safe destroy, esbuild ESM/CJS/browser-global output. Keep browser runtime below 15 KiB gzip. Neutral controls below the picture; no gradients or overlay control slab. An optional image inside a safe SVG marker follows native playback position, with subtle motion only during playback and respect for reduced motion. Theme options belong to each instance; upload/preset UI belongs to host applications.

Small feature scope: accessible native seeking and volume, time/buffer state, 0.5–2× rates, optional VTT caption selection, capability-gated fullscreen/PiP, visible error recovery. No bundled streaming engine, playlist, account, storage or analytics. Local demo and bilingual migration documentation move to the new runtime. Original code license remains, removed Vue runtime is available with its notices in Git history.

Integration contract: default/named Vido, `new Vido({el, video?, src?, poster?, lang?, avatar?, accent?, motion?, tracks?})`; `video`, `src`, `setSource`, `setTheme`, `destroy`. Preserve source children and native video events. Parent coordinator handles website and Ashita integration, artwork, real-browser acceptance and publishing; this workstream changes only the Vido library repository.

Validation: typechecked distribution, strict gzip budget, DOM regressions for source/lifecycle/async races/recovery/avatar security, real-browser regression page and coordinator-owned real media/keyboard/responsive checks. Build and unit tests do not establish device compatibility.
